## 1. 背景与目标

新成员入职后需完成一次「履约参访」作为入职履约环节，本产品为**企业算力（GPU）采购与治理平台**，将算力选型、报价锁价、多级审批、订单支付、实例交付、计费出账、结算、售后闭环线上化。

**核心目标**

- 从真实可售库存出发，生成可解释的算力推荐（AI 仅增强解释，失败降级）。
- 报价、库存变化不破坏已锁价的订单草稿；审批与履约分离。
- 成本以「实例 × 自然日」用量事实计量，FinOps 可复算、口径公开。
- 全程状态可追踪、可审计、可统计，租户数据严格隔离。

**非目标**

- 不接真实 GPU 资源（实例交付为模拟，约 2 秒进入运行中）。
- 不接真实第三方支付（支付仅余额扣减；含模拟充值渠道回调）。
- 竞价实例、SSO/企业微信登录、OpenAPI 文档站不在本版范围。

## 3. 核心业务流程

```
登录/进入角色 → 浏览资源（筛选/对比/估算/评测评价）
  → AI 推荐与证据核验 → 锁价草稿 → 多级审批（V3，审批与履约分离）
  → 人工确认订单 → 支付（余额）→ 实例创建中 → 交付 → SSH 可登录
  → 运行计费（按秒计量）→ 监控/日志/告警/快照/续费/变更配置
  → 释放（数据擦除）→ 按用量事实出账 → 开票/充值支付 → 工单售后
  → 平台与资源方 T+7 结算（佣金 7%）
```

## 4. 功能需求

### 4.1 需求方控制台（/console）
- **概览**：本月消费（按用量事实）、实例状态、预算进度、30 天消费趋势（用量事实）、状态分布、项目利用率（用量事实）。
- **资源市场**：多维筛选、基准分排序、详情（评测基准/用户评论，读真实表）、3 资源对比、成本估算、降价订阅（按登录企业）。
- **创建实例**：4 步向导、费用实时估算、超预算拦截、超阈值触发审批。
- **实例管理**：完整状态机（创建中→运行中→已停止→释放中→已释放、异常、待续费、被回收、恢复中）、真实监控曲线（读指标表）、日志（读日志表）、SSH、快照（创建/恢复）、告警、计费明细（`/instances/:id/usage`）、续费（真实扣费）、变更配置（差价补扣）。
- **账单与发票**：账期账单、真实明细（按用量事实）、余额支付、充值（渠道抽象+回调）、开票申请与进度、结算。
- **组织与项目**：成员邀请/禁用/交接、项目预算、**多级审批人配置**、审计日志。
- **审批中心**：多级审批（V3）、逐级处理、审计轨迹；审批不自动扣费或交付。
- **工单中心**：六类工单、SLA 首响时限、回复流转、**升级与 SLA 达标率统计**。
- **消息中心 / 设置**：分类通知、通知偏好、API 密钥（脱敏）。

### 4.2 资源方后台（/provider，本版修复可达）
- 收益概览（结算收益/利用率/趋势，真实计算）、库存监控。
- 资源上架/下架、实时调价（含审计）、健康分。
- 订单与结算（T+7、佣金 7%）、提现（状态校验+审计）。
- 工单协同（派单接单、SLA 计时）。

### 4.3 平台管理后台（/admin，本版修复可达）
- 平台概览（GMV 趋势/利用率真实计算）、资源方审核（含审计）。
- 市场管理、企业/订单/账单/工单管理（只读）。
- **月度结算引擎**（`/admin/settlements/run`，幂等生成结算单+佣金）、系统公告（按成员企业推送）。

### 4.4 移动端 App（/app）
- 底部 4 Tab：工作台、实例、账单、我的。
- 告警动态（真实告警表）、待办审批、消息中心（分类+未读）、审批处理、新建工单。
- 危险操作二次确认、工单回复（修复回复内容为空的 bug）。

### 4.5 AI 算力决策
- 输入工作负载/模型规模/数据规模/时限/预算/地域/合规 → 输出 3 个可售库存方案。
- 确定性引擎负责价格、库存、性能、排序；AI 仅增强解释，失败明确降级。

### 4.6 FinOps 控制台
- 基于用量事实计算：窗口成本、平均利用率、闲置成本、月度预测、可优化金额、**碳排放**、**成本环比**。
- **按 GPU 型号 / 按资源方**分组、项目分解、优化机会、治理红线（预算暴露 + 闲置策略）。
- 口径、粒度、新鲜度公开。

### 4.7 审批治理（V3）
- 版本化项目策略、多级审批步骤、租户隔离、完整审计。
- 审批决策与履约分离：通过后需独立确认才生成待支付订单。

### 4.8 工单中心
- 六类工单、SLA 首响时限、回复流转、计费争议自动关联。
- **SLA 达标率统计**（首响达标率 + 按类型逾期计数）、**升级动作**（优先级→紧急 + 系统回复 + 通知）、超时标记。

### 4.9 账单/发票/结算/充值
- 账单出账（真实明细来源 usage_records）、余额支付、**充值渠道抽象**（开发直接入账 / 生产支付意向 + 回调）、开票进度推进。
- 平台与资源方 T+7 结算、佣金入库、提现校验。

### 4.10 资源市场与评测
- 资源筛选/排序/对比、**评测基准与用户评论（读真实表 + 可提交评论）**、成本估算、降价订阅。

### 4.11 通知 / 告警 / 审计
- 站内通知（分类、未读、一键已读）、告警列表（企业维度）。
- 审计日志：关键操作留痕（上/下架、调价、审核、充值、续费、变更配置、恢复快照、工单回复/升级等）。

### 4.12 安全与治理
- **租户隔离**：按裸 ID 查对象统一校验 `enterprise_id` 归属；游客锁定演示租户。
- **限流**：游客限流、登录限流 + 失败锁定（IP+账号）、订单/账单写接口限流（可插拔存储）。
- **会话**：账号会话（scrypt 密码）、游客会话、超管测试会话、后台专属会话。
- 安全响应头、会话过期清理、权限门禁（`requireRoles`）。

## 6. 技术架构

- 后端：Express + 内置 `node:sqlite`（WAL），路由按域拆分（auth/market/orders/billing/org/tickets/notifications/provider/admin/dashboard/advisor/finops/approvals-v3）。
- 认证：HMAC 签名会话（普通/游客/超管/后台），scrypt 密码，`security.js` 统一鉴权中间件。
- 前端：React + Vite + Ant Design，四端（console/provider/admin/app），自绘 SVG 图表。
- 生产：`NODE_ENV=production` 单进程托管前端产物，游客只读，后台演示会话关闭。

## 9. 已知边界与后续计划

- 实例交付、监控/日志/用量为模拟数据（未接真实 GPU 与计费系统）。
- 支付仅余额扣减，充值渠道为模拟回调，未接持牌支付。
- 双审批体系已并存（旧 approvals 与 V3）：`orders/create` 仍走旧审批，建议后续统一下单链路到 V3。
- 竞价实例、SSO/企业微信、OpenAPI 文档站、真实鉴权存储（Redis 限流/多实例会话）为后续计划。
- 商业化前需将运行时数据层切换至 `database/postgres/0001_v3_foundation.sql` 提供的托管 PostgreSQL 基线。
